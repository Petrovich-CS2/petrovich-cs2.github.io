## 📌 О проекте

**Counter Chat** — это лёгкий веб-разговорник для игроков Counter-Strike 2, которые
играют в международных лобби, но не уверены в своём английском. Приложение решает
одну конкретную задачу: дать нужную фразу за один тап — с переводом, произношением,
транскрипцией и озвучкой вслух, — не отвлекая от игры.

Работает как обычный сайт в браузере или как полноценное веб-приложение,
устанавливаемое на домашний экран телефона (PWA), в том числе по-настоящему
офлайн — через Service Worker с автоматическим обновлением в фоне.

## 🚀 Быстрый старт

Проект — статический сайт без сборки и зависимостей. Всё, что нужно:

1. Проще всего — открыть готовую версию на GitHub Pages: <https://petrovich-cs2.github.io/>

2. Либо скачать репозиторий к себе на компьютер (**Code → Download ZIP**, или `git clone`) и открыть `index.html` оттуда в браузере — сайт статический и не требует сборки. Открывай его из скачанной папки целиком: иконки категорий, фоны карт и значки лежат рядом, в `assets/`, и без них эти картинки не отобразятся. (Просто открыть `index.html` прямо на сайте GitHub, кликнув по нему в списке файлов, не сработает — GitHub в таком случае покажет исходный код как текст, а не запустит саму страницу.)

### Установка как приложение

| Платформа | Как установить |
| --- | --- |
| **iOS** | Открой сайт в Safari → «Поделиться» → «На экран „Домой“» |
| **Android** | Открой сайт в Chrome → меню (⋮) → «Установить приложение», либо нажми кастомную кнопку установки прямо в шапке приложения (появляется, когда браузер поддерживает такую установку) |

После установки приложение запускается в полноэкранном режиме, со своей иконкой и
загрузочным экраном — как обычное нативное приложение.
Долгий тап по иконке на домашнем экране (Android) открывает быстрые ярлыки — «Избранное» и «Карты».

## 🛠️ Технологии

Никакого фреймворка, никакой сборки — чистый HTML / CSS / JavaScript,
работающий в любом современном браузере.

Бейджи `dependencies-0` и `backend-none` относятся к самому приложению: оно не требует
сборки и собственного сервера. Push-уведомления при этом доставляет внешний сервис OneSignal.

Само приложение — один файл `index.html` (около 370 КБ, порядка 100 КБ при передаче со сжатием), а иконки категорий, фоны карт и значки интерфейса лежат отдельными WebP-файлами в `assets/` — так страница открывается быстрее на медленном мобильном интернете. Service Worker хранит эти картинки в отдельном кэше, который не сбрасывается при каждом обновлении приложения, поэтому после первой загрузки всё работает без интернета. QR-коды (для экспорта фраз) генерируются собственным встроенным кодировщиком — без внешних библиотек.

Публикация на GitHub Pages автоматизирована через GitHub Actions: при каждом
пуше версия кэша и текст мини-changelog подставляются в `sw.js` автоматически,
без ручного редактирования.

## ⚠️ Известные ограничения платформы

Несколько вещей, которые выглядят как баги, но на самом деле являются ограничениями
самих iOS/Android, а не нашего кода:

<details>
<summary><strong>Показать все ограничения (8)</strong></summary>

- **Статус-бар на iOS** — при запуске с домашнего экрана системный статус-бар (время/заряд/вайфай) невозможно скрыть никаким способом через веб-технологии, это осознанное ограничение Apple для веб-приложений.
- **Иконка в меню «Поделиться» на iOS** — если передать в `navigator.share()` одновременно `title`, `text` и `url`, с iOS 13.4 есть задокументированный баг Apple, из-за которого иконка превью пропадает (белая заглушка вместо неё) — подтверждено даже для нативных приложений на [официальном API](https://developer.apple.com/forums/thread/133575). Поэтому в коде `url` намеренно не передаётся.
- **Вибрация на iOS** — `navigator.vibrate()` не поддерживается в Safari ни в каком виде, включая PWA — Apple принципиально не даёт веб-страницам доступ к вибромотору. На Android ощущается, на iPhone просто тихо не срабатывает без ошибок.
- **Кастомная кнопка установки** — работает только на Chromium-браузерах (Android/десктоп). У iOS Safari нет события `beforeinstallprompt` — это не наш недосмотр, а отсутствие этого события в WebKit.
- **Бейдж на иконке** — на iOS работает начиная с 16.4 и только для приложения, добавленного на главный экран, при разрешении на уведомления. В обычной вкладке Safari Badging API недоступен.
- **QR-код открывается в браузере, а не сразу в установленном приложении** — на iOS сканирование через системную камеру всегда открывает ссылку в Safari, даже если то же приложение уже стоит на домашнем экране. Данные при этом всё равно импортируются корректно (`localStorage` общий для браузера и standalone-режима на одном домене) — просто нужно будет вручную открыть свою иконку после.
- **Обнаружение обновлений может занимать до ~10 минут после публикации** — GitHub Pages по умолчанию отдаёт все файлы с заголовком `Cache-Control: max-age=600`, и это касается в том числе системной, полностью браузерной проверки обновления самого `sw.js` (`registration.update()`) — мы не можем повлиять на этот конкретный запрос из своего кода, поскольку он выполняется браузером напрямую, в обход нашего JavaScript. Проверка обновления при каждом возврате в приложение гарантирует, что баннер рано или поздно появится — просто не обязательно сразу после публикации.
- **iOS в standalone-режиме (запуск с домашнего экрана) не всегда ведёт себя как обычная вкладка Safari** — сама ОС может «замораживать» уже открытое веб-приложение при сворачивании, и при следующем открытии просто восстанавливать его из памяти, а не запускать заново по-настоящему — из-за этого некоторые события браузера (`load`, иногда даже `pageshow`) могут не срабатывать в отдельных сессиях, хотя сам JS-код продолжает работать корректно. Регистрация Service Worker в коде намеренно не полагается на эти события и запускается сразу же, без ожидания.

</details>
